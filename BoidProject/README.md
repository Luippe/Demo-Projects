An interactive [boids](https://en.wikipedia.org/wiki/Boids) flocking simulation.
Agents follow the classic separation / alignment / cohesion rules to produce
emergent flocking behaviour, with obstacles you can place and toggleable screen
borders.

> This is the only **Java** project in the collection — it doesn't use Python and
> has no `requirements.txt`. The downloadable `.zip` bundles its own Java runtime,
> so nothing needs to be installed to play with it.

## Controls

| Input | Action |
|-------|--------|
| Left-click | Add a boid |
| Right-click | Add / remove an obstacle |
| `W` / `A` / `S` / `D` | Move the view |
| `Space` | Toggle the visible screen borders (on by default) |
| Close the window | Quit |

## Run from source

Needs **JDK 17 or newer** (`javac` and `java` on your PATH — check with
`java -version`). No external libraries are needed; it's plain Swing.

From inside the `BoidProject` folder:

```powershell
# Compile the sources into bin/
$sources = Get-ChildItem src\main\*.java, src\entity\*.java
javac -d bin $sources.FullName

# Run the Main class
java -cp bin main.Main
```

The window opens maximized.

You can also open this folder in VS Code with the *Extension Pack for Java*
installed and press **Run** — `.vscode/settings.json` already points source at
`src/` and output at `bin/`.

## Build the Windows application

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\Build-Boids.ps1
```

This produces `..\dist\Boids\Boids.exe` (the portable launcher — keep the whole
`Boids` folder together, it holds the bundled runtime) and `..\dist\Boids-Windows.zip`,
which is what the download button above serves. Adding `-Type Installer` builds a
Windows installer instead, at `..\dist\Boids.exe`; that requires WiX.

## Project layout

- `src/main/` — entry point (`Main.java`), rendering, input handling, obstacles, and spawning.
- `src/entity/` — `Entity` and `Enemy` agent classes.
- `test/` — dependency-free simulation and rendering smoke test, run automatically on every build.
- `bin/` — compiled `.class` output (git-ignored; regenerated by `javac`).
